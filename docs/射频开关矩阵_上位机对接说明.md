### 2.1 为什么新增 `IOutputSwitcher` 而不是扩展 `IChannelSwitcher`

「通道间隔离度」测试（规划书 §4.3.5 第 16 项，当前为 Stub）需要 **RF 输入通道 ≠ 输出读数通道**：

```
RF 信号源 → A 组（切 CH1）→ 接收机 CH1 的 RF 口（注入强信号）
                                      ↓ 接收机内部串扰
接收机 CH2 的 IF 输出口 → B 组（切 CH2）→ 频谱仪（读漏过来的信号）
```

因此矩阵必须支持输出路独立切换。

`IChannelSwitcher` 的签名在 M3 阶段**已冻结**（`.trae/specs/bootstrap-development-process/spec.md` M3 退出条件："接口签名冻结并通过评审"）。破坏它会影响既有评审记录。

**方案乙（另立接口）的优势**：
- 不动已冻结的接口
- 输出路切换是独立职责，独立接口更符合项目的"接口隔离"原则
- `MatrixSerialPort` 是同一个对象，**共用同一个串口连接**，UI 侧只需持有一个实例

```csharp
namespace A205AutoTestSystem.MatrixControl
{
    /// <summary>
    /// 矩阵输出路（中频）通道切换抽象接口。
    /// </summary>
    public interface IOutputSwitcher
    {
        /// <summary>切换输出路到指定通道（1..8）。</summary>
        void SwitchOutputChannel(int channel);

        /// <summary>同时设置 A 组（RF/LO）与 B 组（输出路）通道。</summary>
        void SetChannels(int channelA, int channelB);
    }
}
```

## 三、`MatrixCommandBuilder.cs` 设计

### 3.1 职责边界

| 做 | 不做 |
|---|---|
| 构造请求帧（切通道、隔离、查询） | 不碰串口 |
| 解析响应帧（提取 cmd / status / payload） | 不做超时控制 |
| 计算 Sum8 校验和 | 不记日志 |
| 维护通道号合法性校验 | 不决定何时调用 |

### 3.2 常量定义

```csharp
public static class MatrixCommandBuilder
{
    // ── 帧头 ──
    public const byte FrameHeader1 = 0xAA;
    public const byte FrameHeader2 = 0x55;

    // ── 命令码：A 组（RF 路 + LO 路）──
    public const byte CmdSwitchChannel  = 0x01;
    public const byte CmdIsolateA      = 0x02;
    public const byte CmdQueryChannelA = 0x03;

    // ── 命令码：公共 ──
    public const byte CmdQueryVersion = 0x04;
    public const byte CmdReset        = 0x05;

    // ── 命令码：B 组（输出路）──
    public const byte CmdSwitchChannelB = 0x06;
    public const byte CmdIsolateB      = 0x07;
    public const byte CmdQueryChannelB = 0x08;

    // ── 命令码：双组同时设置 ──
    public const byte CmdSetBothChannels = 0x09;

    // ── 状态码 ──
    public const byte StatusOk            = 0x00;
    public const byte StatusCrcError      = 0x01;
    public const byte StatusRangeError    = 0x02;
    public const byte StatusUnknownCmd    = 0x03;
    public const byte StatusFrameError    = 0x04;
    public const byte StatusInternalError = 0x05;

    // ── 约束 ──
    public const int MinChannel = 1;
    public const int MaxChannel = 8;
    public const int MaxPayloadLength = 32;
}
```

### 3.3 方法签名

### 3.4 响应模型

{
    /// <summary>回显的命令码。</summary>

### 3.5 帧构造实现要点

```csharp
public static byte[] BuildSwitchChannel(int channel)
{
    if (channel < MinChannel || channel > MaxChannel)
    {
        return null;   // 越界由调用方记日志
    }

    byte[] frame = new byte[5];
    frame[0] = FrameHeader1;
    frame[1] = FrameHeader2;
    frame[2] = CmdSwitchChannel;
    frame[3] = 0x01;          // LEN
    frame[4] = (byte)channel;
    frame[4 + 1] = CalculateChecksum(frame, 5);   // 校验写入第 5 字节
    return frame;
}
```

> 注意：`CalculateChecksum(frame, length)` 的 `length` 参数指**参与求和的字节数**（不含校验字节本身）。

### 3.6 解析实现要点

解析要处理三种异常：

| 异常 | 判定 | 返回 |
|---|---|---|
| 帧头不符 | `buffer[0] != 0xAA \|\| buffer[1] != 0x55` | false |
| 长度不足 | `length < 5` | false |
| LEN 越界 | `buffer[3] > MaxPayloadLength` | false |
| 帧长不足 | `length < 5 + buffer[3]` | false |
| 校验不符 | 重算 Sum8 与末字节比较 | false |

**解析失败时不抛异常**，一律返回 false，由调用方记日志。

### 3.7 接收缓冲策略

串口是**字节流**，一次 `DataReceived` 事件可能带来半帧或两帧。

`MatrixSerialPort` 内部维护一个 `List<byte>` 缓冲：

```
DataReceived(buffer)
    ↓
追加到 _rxBuffer
    ↓
循环：尝试从 _rxBuffer 头部解析完整帧
    ├─ 成功 → 处理，移除已消费字节，继续解析下一帧
    ├─ 帧头不符 → 丢弃第一个字节，重试（帧头同步）
    └─ 长度不足 → break，等更多数据
```

**必须支持一帧拆多次到达和多帧一次到达两种情况** —— 这是串口通信的常态。

## 四、`MatrixSerialPort.cs` 重写

### 4.1 类结构

```csharp
public class MatrixSerialPort : SerialPortBase, IChannelSwitcher, IOutputSwitcher
{
    private readonly List<byte> _rxBuffer = new List<byte>();
    private readonly object _rxLock = new object();

    private bool _isConnected;
    private byte _lastStatus;

    // 事件
    public event Action<bool> ConnectionChanged;

    // IChannelSwitcher
    public bool IsConnected => _isConnected;

    // ⚠️ 命名冲突注意：基类 SerialPortBase 已有 PortName（只读，取自 SerialPort）。
    //    IChannelSwitcher 也要求 PortName —— 基类已满足接口，不要重复声明。
    //    若基类版本不适用（未打开时返回 null），改为重写为返回存储的端口名。
}
```

> `MatrixSerialPort` 同时实现两个接口，但**共用同一个串口连接**，不需要开两个串口。

### 4.2 `Connect` 实现

```csharp
public void Connect(string portName, int baudRate = 115200)
{
    try
    {
        Open(portName, baudRate);          // SerialPortBase.Open，内部已记日志

        // 连接即校验：发版本查询，确认固件在线且协议匹配
        byte[] versionFrame = MatrixCommandBuilder.BuildSimpleCommand(
            MatrixCommandBuilder.CmdQueryVersion);

        SendBytes(versionFrame);

        if (!WaitForResponse(MatrixCommandBuilder.CmdQueryVersion, 500))
        {
            Logger.Log("[Matrix] 版本查询超时，判定为未连接。");
            Close();
            ConnectionChanged?.Invoke(false);
            return;
        }

        _isConnected = true;
        Logger.Log($"[Matrix] 连接成功：{portName} @ {baudRate}");
        ConnectionChanged?.Invoke(true);
    }
    catch (Exception ex)
    {
        Logger.Log($"[Matrix] 连接失败：{ex.Message}");
        try { Close(); } catch { }
        _isConnected = false;
        ConnectionChanged?.Invoke(false);
    }
}
```

**关键点**：

1. **版本查询作为连通性校验** —— 避免"串口打开但固件不响应"被误判为已连接。这正是当前桩实现的核心问题（`IsConnected` 恒 false 但 UI 显示"已请求连接"）。
2. **失败不抛异常** —— `OnMatrixConnectClicked` 已有 try/catch 会弹 MessageBox；连接失败只记日志更符合项目既有约定（其他仪表的连接失败也是记日志不弹窗）。
3. **失败后必须关闭串口** —— 否则串口处于半开状态。

### 4.3 `Disconnect` 实现

```csharp
public void Disconnect()
{
    try
    {
        if (_isConnected)
        {
            // 先发全隔离，确保射频通路断开
            byte[] iso = MatrixCommandBuilder.BuildSimpleCommand(
                MatrixCommandBuilder.CmdIsolateAll);
            SendBytes(iso);
        }
    }
    catch (Exception ex)
    {
        Logger.Log($"[Matrix] 隔离命令发送失败（忽略）：{ex.Message}");
    }

    try { Close(); } catch { }

    lock (_rxLock) { _rxBuffer.Clear(); }

    _isConnected = false;
    Logger.Log("[Matrix] 已断开。");
    ConnectionChanged?.Invoke(false);
}
```

**为什么断开时先发隔离**：让矩阵进入全 50 Ω 终端状态，避免测试结束后信号源功率仍经矩阵泄漏到某个通道。

### 4.4 `SwitchChannel` 实现（A 组）

```csharp
public void SwitchChannel(int channel)
{
    if (!_isConnected)
    {
        Logger.Log($"[Matrix] 切换通道 {channel} 失败：矩阵未连接。");
        return;
    }

    byte[] frame = MatrixCommandBuilder.BuildSwitchChannel(channel);
    if (frame == null)
    {
        Logger.Log($"[Matrix] 切换通道失败：通道号 {channel} 超出 1~8 范围。");
        return;
    }

    SendBytes(frame);   // SerialPortBase.SendBytes 自动 Logger.LogSend

    if (!WaitForResponse(MatrixCommandBuilder.CmdSwitchChannel, 500))
    {
        Logger.Log($"[Matrix] 切换通道 {channel} 超时（500 ms）。");
        return;
    }

    if (_lastStatus != MatrixCommandBuilder.StatusOk)
    {
        Logger.Log($"[Matrix] 切换通道 {channel} 失败：状态码 0x{_lastStatus:X2}。");
    }
}
```

**设计约定**：

| 约定 | 理由 |
|---|---|
| 返回 `void` | `IChannelSwitcher` 接口冻结，不改签名 |
| 失败**只记日志**，不抛异常 | 与项目既有约定一致（见 `OnModeChanged` 中仪表失败也是记日志不弹窗） |
| 失败**必须记日志** | 矩阵通道与接收机通道不匹配时，测试数据完全失真，静默失败是最危险的 |
| 超时 500 ms | PE42482 切换仅 227 ns，ACK 主要来自 MCU 串口处理，500 ms 极宽裕 |
| 不做重试 | 单次失败即记日志，避免阻塞 UI 线程。重试策略放在上层调用方 |

> 若后续确认固件偶发丢帧，可在 `SwitchChannel` 内加重试（最多 3 次、间隔 100 ms），但要注意 UI 线程阻塞时间。

### 4.4.1 `SwitchOutputChannel` 与 `SetChannels`（B 组 / 双组）

```csharp
/// <summary>切换输出路（B 组）到指定通道。不影响 A 组。</summary>
public void SwitchOutputChannel(int channel)
{
    if (!_isConnected)
    {
        Logger.Log($"[Matrix] 切换输出通道 {channel} 失败：矩阵未连接。");
        return;
    }

    byte[] frame = MatrixCommandBuilder.BuildSwitchChannelB(channel);
    if (frame == null)
    {
        Logger.Log($"[Matrix] 切换输出通道失败：通道号 {channel} 超出 1~8 范围。");
        return;
    }

    SendBytes(frame);

    if (!WaitForResponse(MatrixCommandBuilder.CmdSwitchChannelB, 500))
    {
        Logger.Log($"[Matrix] 切换输出通道 {channel} 超时（500 ms）。");
        return;
    }

    if (_lastStatus != MatrixCommandBuilder.StatusOk)
    {
        Logger.Log($"[Matrix] 切换输出通道 {channel} 失败：状态码 0x{_lastStatus:X2}。");
    }
}

/// <summary>同时设置 A 组与 B 组通道（原子切换，CMD 0x09）。</summary>
public void SetChannels(int channelA, int channelB)
{
    if (!_isConnected)
    {
        Logger.Log($"[Matrix] 设置通道失败：矩阵未连接。");
        return;
    }

    byte[] frame = MatrixCommandBuilder.BuildSetBothChannels(channelA, channelB);
    if (frame == null)
    {
        Logger.Log($"[Matrix] 设置通道失败：通道号 [{channelA}, {channelB}] 超出 1~8 范围。");
        return;
    }

    SendBytes(frame);

    if (!WaitForResponse(MatrixCommandBuilder.CmdSetBothChannels, 500))
    {
        Logger.Log($"[Matrix] 设置通道 [{channelA}, {channelB}] 超时（500 ms）。");
        return;
    }

    if (_lastStatus != MatrixCommandBuilder.StatusOk)
    {
        Logger.Log($"[Matrix] 设置通道 [{channelA}, {channelB}] 失败：状态码 0x{_lastStatus:X2}。");
    }
}
```

> **`SetChannels` 的原子性优势**：两组状态在 < 1 µs 内同时改变，接收机不会看到中间态。
> 常规测试（chA = chB）与隔离度测试（chA ≠ chB）都推荐用它。

### 4.5 响应等待机制

```csharp
private bool WaitForResponse(byte expectedCmd, int timeoutMs)
{
    DateTime start = DateTime.Now;
    while ((DateTime.Now - start).TotalMilliseconds < timeoutMs)
    {
        if (_lastHandledCmd == expectedCmd && _responseReceived)
        {
            _responseReceived = false;
            return true;
        }
        Thread.Sleep(10);
    }
    return false;
}
```

**注意**：这个 `while + Thread.Sleep` 会在 UI 线程上阻塞最多 500 ms。

**改进方向**（M6 阶段考虑）：改为 `ManualResetEventSlim` 或 `Task` 异步等待。当前项目已有 `Thread.Sleep` 阻塞的既有问题（见代码审查报告 #30），新增代码不应放大这个模式。

| T9 | LEN 越界 | LEN = 0xFF | false |
| T10 | 长度不足 | 截断帧 | false |
| T11 | 状态码转文本 | 各状态码 | 返回可读描述 |
| T12 | 往返一致性 | 构造帧 → 模拟响应 | 解析出的 cmd 与 payload 正确 |
| **T13** | **B 组切通道帧构造** | ch=3 | `AA 55 06 01 03 06` |
| **T14** | **B 组越界返回 null** | ch=0 / 9 | null |
| **T15** | **双组同时设置帧构造** | (1, 2) | `AA 55 09 02 00 01 02 09` |
| **T16** | **双组设置越界返回 null** | (1, 0) | null（**两组均不改变**） |
| **T17** | **命令码唯一性** | 遍历 0x01~0x09 | 各命令码互不重复 |
| **T18** | **B 组响应解析** | 模拟 B 组 ACK | Cmd 回显 0x06 |

### 5.3 帧构造的期望值（手算校验）

**校验字节 = (0xFF + CMD + LEN + PAYLOAD 各位之和) & 0xFF**（因 0xAA + 0x55 = 0xFF）

```
切通道 1:  AA 55 01 01 01 → 0xFF+0x01+0x01+0x01 = 0x102 → 0x02
切通道 8:  AA 55 01 01 08 → 0xFF+0x01+0x01+0x08 = 0x109 → 0x09
全隔离:    AA 55 02 00    → 0xFF+0x02+0x00       = 0x101 → 0x01
查询状态:  AA 55 03 00    → 0xFF+0x03+0x00       = 0x102 → 0x02
版本查询:  AA 55 04 00    → 0xFF+0x04+0x00       = 0x103 → 0x03
```

**预期完整帧**：

| 用例 | 完整帧 |
|---|---|
| T1 A 组切通道 1 | `AA 55 01 01 01 02` |
| T2 A 组切通道 8 | `AA 55 01 01 08 09` |
| T4 隔离 A 组 | `AA 55 02 00 01` |
| 查询 A 组状态 | `AA 55 03 00 02` |
| 版本查询 | `AA 55 04 00 03` |
| 双组复位 | `AA 55 05 00 04` |
| **T13 B 组切通道 3** | `AA 55 06 01 03 06` |
| **隔离 B 组** | `AA 55 07 00 05` |
| **查询 B 组状态** | `AA 55 08 00 07` |
| **T15 双组同时设置 (1,2)** | `AA 55 09 02 00 01 02 09` |

> 这些值来自手算，单元测试直接锁定。**若实现后测试不通过，以 `CalculateChecksum` 的实际计算为准**（说明手算有误），并回填本文档。

## 六、`ReceiverControlPanel.cs` 的可选小改

UI **不需要新增控件**，但建议改一处：

### 6.1 连接状态反馈

当前桩实现下，`OnMatrixConnectClicked` 无论成败都只记一行日志：

```csharp
_matrix.Connect(portName, baudRate);
// MatrixSerialPort 桩的 IsConnected 始终返回 false，
// 因此用本地标志位来反映"UI 已请求连接"。
// M3 协议到位后，可改为订阅 ConnectionChanged 事件。
Logger.Log($"[UI] Matrix connect requested on {portName} @ {baudRate}.");
```

**M3 落地后建议**：

```csharp
_matrix.ConnectionChanged += OnMatrixConnectionChanged;
```

并在处理函数中更新状态显示（若面板上有状态标签）。

> 需要先确认 `grpSerialConnection` 区域是否有矩阵状态标签。从 Designer 看，`grpSerialConnection` 内有 `lblMatrixSerial`（这是**串口标签**，不是状态标签）。若要显示连接状态，需新增一个 Label —— 这属于**可选的 UI 增强**，不阻塞 M3 交付。

### 6.2 `OnChannelSelected` 的异常处理

当前已有 try/catch，足够。但 `SwitchChannel` 改为"只记日志不抛异常"后，这段 catch 基本不会触发 —— **保留无害**。

### 6.3 通道切换与接收机的时序

**重要**：现有约定是"通道下拉框只切换矩阵，接收机通道命令由 `btnModeSet` 随模式下发"。

矩阵切换 ACK 最多阻塞 500 ms（超时情况）。`btnModeSet` 的顺序是：

```
通道帧 → 100 ms → 模式序列
```

**建议**：在 `btnModeSet` 中，发送接收机通道帧**之前**先确保矩阵已切到对应通道。当前顺序是"矩阵（下拉）→ 接收机（btnModeSet）"，用户操作上已天然有序。

若后续要自动化（自动测试遍历通道），需在测试引擎中确保：

```
Matrix.SwitchChannel(n)  →  等 ACK  →  间隔 100 ms  →  Receiver.SendChannelCommand(n)
```

## 八、风险与注意事项

| # | 风险 | 应对 |
|---|---|---|
| 1 | 协议在固件开发中被调整 | 变更集中在 `MatrixCommandBuilder.cs`，用版本号（CMD 0x04）识别不兼容 |
| 2 | `WaitForResponse` 在 UI 线程阻塞 | 500 ms 上限可接受；M6 阶段考虑异步化 |
| 3 | 矩阵切换失败被静默忽略 | **所有失败路径必须记日志**，联调时逐条核对日志 |
| 4 | 串口粘包/拆包处理不当导致状态错乱 | 单元测试必须覆盖 T6、T10 及多帧连续到达场景 |
| 5 | 通道映射错误（固件侧） | 固件用查表 + 必须实测；上位机可增加"查询当前通道"交叉校验 |
| 6 | `IChannelSwitcher` 接口签名不够用 | 采用**方案乙**（另立 `IOutputSwitcher`），不动已冻结接口 |
| 7 | **A/B 两组编码表不一致** | 实测时**分别验证两组**；固件保留两张表结构，即使当前值相同 |
| 8 | **B 组切换被误当作全局切换** | `IOutputSwitcher` 方法命名明确含 "Output"；日志前缀区分 A/B 组 |
