# A205 射频开关矩阵 —— 通信协议规范

> 文档用途：驱动板固件与 A205 上位机之间的串口协议定义
> 编写日期：2026-10-27
> 状态：草案，待评审
> 配套文档：`docs/射频开关矩阵_驱动板规格书.md`

---

## 一、设计目标与约束

| 项目 | 取值 | 说明 |
|---|---|---|
| 物理层 | USB 转串口（CH340C / CP2102） | Windows 枚举为 `COMx` |
| 波特率 | **115200** | 上位机 `cmbMatrixBaud` 默认已含此值 |
| 数据位 / 校验 / 停止位 | 8 / None / 1 | 与既有 `SerialPortBase` 默认一致 |
| 流控 | None | |
| 字节序 | — | 多字节字段一律 **大端（高字节在前）** |
| 编码 | ASCII 十六进制或原始二进制 | **采用原始二进制**（见下） |

**为何用原始二进制而非 ASCII 十六进制**：

接收机协议（`0D 11 CH P 00 00 0A`）已是原始二进制形式。矩阵协议保持一致风格，便于统一日志格式（`Logger.LogSend` 已按字节数组格式化），且帧长更短。

## 二、帧格式

### 2.1 通用帧结构

```
┌────────┬────────┬────────┬──────────────┬──────────────┐
│ 0xAA   │ 0x55   │  CMD   │   PAYLOAD    │    CHECK     │
│  帧头1 │  帧头2 │ 命令码 │  长度 + 数据  │   Sum8 校验  │
│ 1 字节 │ 1 字节 │ 1 字节 │  1 + N 字节  │   1 字节     │
└────────┴────────┴────────┴──────────────┴──────────────┘
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 帧头 | 2 | 固定 `0xAA 0x55`。用于快速丢弃噪声字节 |
| CMD | 1 | 命令码，见 §3 |
| LEN | 1 | PAYLOAD 数据字节数 N（0 ~ 32） |
| PAYLOAD | N | 命令相关数据 |
| CHECK | 1 | Sum8 累加和 |

**校验算法**（Sum8）：

```csharp
byte sum = 0;
foreach (byte b in frame[0 .. frame.Length - 1])   // 不含 CHECK 自身
    sum += b;                                       // 溢出自然截断为低 8 位
frame[frame.Length - 1] = sum;
```

即：CHECK = (0xAA + 0x55 + CMD + LEN + PAYLOAD 各字节之和) & 0xFF。

**校验范围**：从帧头到 PAYLOAD 末尾，**不含 CHECK 字节本身**。

### 2.2 最小帧长

无负载命令：`AA 55 CMD 00 CS` = **5 字节**

接收端按帧头同步：搜索到 `0xAA 0x55` 后读取 LEN，再等待 LEN 个 PAYLOAD 字节 + 1 个 CHECK。

### 2.3 帧示例

| 场景 | 字节流 |
|---|---|
| 切通道 3 | `AA 55 01 01 03 04` |
| 全隔离 | `AA 55 02 00 01` |
| 查询状态 | `AA 55 03 00 02` |
| 版本查询 | `AA 55 04 00 03` |

校验示例（切通道 3）：
```
0xAA + 0x55 + 0x01 + 0x01 + 0x03 = 0x104 → &0xFF = 0x04
```

**校验和速查**（Sum8 = 所有参与字节之和取低 8 位）：

| 帧 | 求和 | 校验字节 |
|---|---|---|
| `AA 55 01 01 01` | 0x102 | `0x02` |
| `AA 55 01 01 08` | 0x109 | `0x09` |
| `AA 55 02 00` | 0x101 | `0x01` |
| `AA 55 03 00` | 0x102 | `0x02` |
| `AA 55 04 00` | 0x103 | `0x03` |
| `AA 55 05 00` | 0x104 | `0x04` |

> 帧头 `0xAA + 0x55 = 0xFF`，这是简化计算的基础：**校验字节 = (0xFF + CMD + LEN + PAYLOAD 各位之和) & 0xFF**。

## 三、控制分组与命令码

### 3.1 控制分组定义

矩阵的射频通路分为两组，**独立控制**：

| 组 | 覆盖模块 | 信号 | 用途 |
|---|---|---|---|
| **A 组** | 圆盘 #1（RF 路）+ 圆盘 #2（LO 路） | V1 / V2 / V3 / V4 | RF 与 LO 始终成对作用于同一接收通道，共用控制线天然同步 |
| **B 组** | 圆盘 #3（输出路） | V1' / V2' / V3' / V4' | 需独立于 A 组切换，用于「通道间隔离度」测试 |

**为什么必须分两组**：

「通道间隔离度」测试需要构造「RF 输入通道 ≠ 输出读数通道」的场景：

```
RF 信号源 → A 组（切 CH1）→ 接收机 CH1 的 RF 口（注入强信号）
                                      ↓ 接收机内部串扰
接收机 CH2 的 IF 输出口 → B 组（切 CH2）→ 频谱仪（读漏过来的信号）
```

若三块模块共用一组控制线，此场景无法构造，隔离度测试只能得到恒定无效的结果。

> 项目规划书 §4.3.5 第 16 项「通道间隔离度」当前为 ⬜ Stub 占位，正是等待该能力落地。

### 3.2 命令一览

| CMD | 名称 | 作用组 | PAYLOAD | 响应 |
|---|---|---|---|---|
| `0x01` | 切换通道 | **A 组** | `[ch]`（1 字节，值 1~8） | ACK |
| `0x02` | 隔离 A 组 | A 组 | 无 | ACK |
| `0x03` | 查询 A 组当前通道 | A 组 | 无 | ACK + 当前通道 |
| `0x04` | 查询固件版本 | — | 无 | ACK + 版本字符串 |
| `0x05` | 复位为隔离态 | 双组 | 无 | ACK |
| `0x06` | **切换输出路通道** | **B 组** | `[ch]`（1 字节，值 1~8） | ACK |
| `0x07` | **隔离输出路** | **B 组** | 无 | ACK |
| `0x08` | **查询输出路当前通道** | **B 组** | 无 | ACK + 当前通道 |
| `0x09` | **同时设置两路** | A + B | `[chA, chB]` | ACK |

### 3.3 CMD 0x01 — 切换 A 组通道（RF 路 + LO 路）

**请求**：

| 字段 | 值 |
|---|---|
| CMD | `0x01` |
| LEN | `0x01` |
| PAYLOAD[0] | 通道号 ch，**取值 1~8** |

**成功响应**：见 §4.1，`STATUS = 0x00`

**失败响应**：§4.1，`STATUS = 0x02`（通道越界）

**固件行为**：

```
1. 校验 ch ∈ [1, 8]，否则回错误 ACK，状态不变
2. V4 = 1                （A 组全隔离）
3. V1~V3 = 编码[ch]      （查表，见驱动板规格书 §5.5）
4. V4 = 0                （解除隔离）
5. 回 ACK（STATUS = 0x00）
```

**幂等性**：重复发送同一通道的命令，必须重复返回成功 ACK，且不产生任何状态变化。

### 3.4 CMD 0x02 — 隔离 A 组

置 `V4 = 1`，A 组（RF 路 + LO 路）所有端口 50 Ω 终端吸收。

**用途**：
- 测试开始前的安全初始态
- 上位机主动断开射频激励通路
- 固件复位后的默认状态

**请求**：`AA 55 02 00 01`
**响应**：ACK（STATUS = 0x00）

### 3.5 CMD 0x03 — 查询 A 组当前通道

**请求**：`AA 55 03 00 02`

**响应**：ACK + PAYLOAD[0] = 当前通道号（1~8）。

若 A 组处于隔离态，PAYLOAD[0] = `0x00`。

**用途**：上位机连接后校验矩阵实际状态与 UI 显示是否一致；长时间运行后的状态自检。

### 3.6 CMD 0x04 — 查询固件版本

**请求**：`AA 55 04 00 03`

**响应**：ACK + PAYLOAD = 版本字符串，格式 `Lx.y.z`（ASCII，如 `L1.0.0`），长度写在 LEN 字段。

**用途**：上位机连上后先查版本，确认固件与协议版本匹配。

### 3.7 CMD 0x05 — 复位为隔离态

置 `V4 = 1` 且 `V4' = 1`，**双组同时隔离**。

等价于 CMD 0x02 + CMD 0x07，但语义为「整体复位」，且是原子的（两组同时进入隔离）。

**请求**：`AA 55 05 00 04`
**响应**：ACK（STATUS = 0x00）

### 3.8 CMD 0x06 — 切换 B 组通道（输出路）

与 CMD 0x01 完全对称，但作用于 B 组（输出路），使用 V1'~V3' / V4'。

**请求**：`AA 55 06 01 03 06`
**成功响应**：ACK（STATUS = 0x00）
**失败响应**：ACK（STATUS = 0x02，通道越界）

**固件行为**：

```
1. 校验 ch ∈ [1, 8]，否则回错误 ACK，状态不变
2. V4' = 1               （B 组全隔离）
3. V1'~V3' = 编码[ch]    （查表，同一张表）
4. V4' = 0               （解除隔离）
5. 回 ACK（STATUS = 0x00）
```

> **B 组使用与 A 组相同的通道编码表** —— 两块是同型号芯片，控制逻辑一致。
> 但**仍必须实测确认**：若三块模块的 LS 接法不一致（一块正码、一块反码），则编码表不同。
> 因此实测时应**分别验证 A 组与 B 组**。

### 3.9 CMD 0x07 — 隔离 B 组

置 `V4' = 1`，输出路所有端口 50 Ω 终端吸收。

**请求**：`AA 55 07 00 05`
**响应**：ACK（STATUS = 0x00）

### 3.10 CMD 0x08 — 查询 B 组当前通道

**请求**：`AA 55 08 00 07`

**响应**：ACK + PAYLOAD[0] = 当前通道号（1~8）；隔离态时为 `0x00`。

### 3.11 CMD 0x09 — 同时设置两路通道

一次命令同时设置 A 组与 B 组，**减少串口往返与中间态**。

**请求**：

| 字段 | 值 |
|---|---|
| CMD | `0x09` |
| LEN | `0x02` |
| PAYLOAD[0] | A 组通道号 chA，1~8 |
| PAYLOAD[1] | B 组通道号 chB，1~8 |

**响应**：ACK（STATUS = 0x00）；任一通道号越界则整体失败，**两组状态均不变**。

**固件行为**：

```
1. 校验 chA 与 chB 均 ∈ [1, 8]，否则回错误 ACK，两组状态均不变
2. V4 = 1 且 V4' = 1     （双组隔离）
3. V1~V3 = 编码[chA]；V1'~V3' = 编码[chB]
4. V4 = 0 且 V4' = 0     （双组解除隔离）
5. 回 ACK（STATUS = 0x00）
```

**典型用例**：常规测试中 chA = chB（两者同通道）。隔离度测试中 chA ≠ chB。

> **原子性说明**：步骤 2~4 的两组状态切换间隔 < 1 µs，远小于接收机建立时间（数十 ms），
> 因此即使两组不同步，接收机也不会看到中间态。

## 四、响应帧

### 4.1 ACK 帧结构

```
┌────────┬────────┬────────┬──────────────┬──────────────┬──────────────┐
│ 0xAA   │ 0x55   │  CMD   │     LEN      │   STATUS     │    CHECK     │
│  帧头1 │  帧头2 │ 回显原 │  1 + N 字节  │   状态码     │   Sum8 校验  │
└────────┴────────┴────────┴──────────────┴──────────────┴──────────────┘
```

| 字段 | 说明 |
|---|---|
| CMD | **回显请求的命令码**（不是独立的 ACK 命令码） |
| LEN | 1 + 数据长度 |
| PAYLOAD[0] | **STATUS** 状态码 |
| PAYLOAD[1..] | 命令相关数据（可选） |

### 4.2 状态码

| STATUS | 名称 | 含义 |
|---|---|---|
| `0x00` | OK | 命令执行成功 |
| `0x01` | CRC_ERROR | 校验和不匹配，命令未执行 |
| `0x02` | RANGE_ERROR | 通道号越界（不在 1~8），命令未执行 |
| `0x03` | UNKNOWN_CMD | 未知命令码，命令未执行 |
| `0x04` | FRAME_ERROR | 帧结构错误（LEN 超出上限、帧长不足等） |
| `0x05` | INTERNAL_ERROR | 固件内部异常 |

**关键约定**：**除 `0x00` 外，所有状态码都表示命令未被执行，矩阵状态保持不变。**

### 4.3 响应示例

**校验字节 = (0xFF + CMD + LEN + PAYLOAD 各位之和) & 0xFF**

| 场景 | 字节流 | 校验手算 |
|---|---|---|
| A 组切通道 3 成功 | `AA 55 01 01 00 01` | 0xFF+0x01+0x01+0x00 = 0x101 → 0x01 |
| A 组切通道 3 成功（带通道回读） | `AA 55 01 02 00 03 05` | 0xFF+0x01+0x02+0x00+0x03 = 0x105 → 0x05 |
| A 组切通道 9 失败（越界） | `AA 55 01 01 02 03` | 0xFF+0x01+0x01+0x02 = 0x103 → 0x03 |
| 校验错误 | `AA 55 01 01 01 02` | 0xFF+0x01+0x01+0x01 = 0x102 → 0x02 |
| 查询 A 组当前通道 = 3 | `AA 55 03 01 00 03 06` | 0xFF+0x03+0x01+0x00+0x03 = 0x106 → 0x06 |
| B 组切通道 3 成功 | `AA 55 06 01 00 06` | 0xFF+0x06+0x01+0x00 = 0x106 → 0x06 |
| B 组隔离 | `AA 55 07 00 05` | 0xFF+0x07+0x00 = 0x106 → 0x06 |
| 双组复位 | `AA 55 05 00 04` | 0xFF+0x05+0x00 = 0x104 → 0x04 |
| 同时设置 A=1 B=2 | `AA 55 09 02 00 01 02 09` | 0xFF+0x09+0x02+0x00+0x01+0x02 = 0x10D → 0x0D |
| 版本查询 `L1.0.0` | `AA 55 04 06 00 4C 31 2E 30 2E 30 XX` | 0xFF+0x04+0x06+0x00+(ASCII 'L1.0.0' 之和) |

> 版本帧的校验字节取决于 ASCII 码之和，实现时由 `CalculateChecksum` 计算并用单元测试锁定，然后回填本表。

## 五、时序要求

### 5.1 单命令交互

```
上位机                              驱动板
   │                                   │
   │──── CMD 0x01 (切通道 ch) ─────────►│
   │                                   │ 执行切换（< 1 µs）
   │◄─── ACK (STATUS=0x00) ────────────│
   │                                   │
```

| 参数 | 要求 |
|---|---|
| ACK 超时 | **500 ms**（上位机侧） |
| 重试 | 最多 **3 次**，间隔 100 ms |
| 重试策略 | 仅对**无响应**重试；收到错误 ACK **不重试**（重试同样的非法命令无意义） |

**说明**：PE42482 开关时间仅 227 ns，ACK 延迟主要来自 MCU 的串口收发与上位机轮询周期，500 ms 极为宽裕。

### 5.2 命令流水线（可选）

固件应支持**连续接收**：上一条命令的 ACK 尚未发完时到达的新命令，进入缓冲区排队处理。

上位机**默认不使用流水线**（每次切通道都等 ACK），保证时序确定、便于日志排查。

### 5.3 切换与接收机命令的时序配合

矩阵切通道与接收机通道命令必须**顺序执行**，中间留间隔。

```
① 矩阵切到 CH n        （等 ACK）
② ── 间隔 ≥ 100 ms ──
③ 接收机发 0D 11 n P 00 00 0A
```

**为什么需要间隔**：PE42482 切换在 1 µs 内完成，但接收机的通道选择命令涉及内部模拟电路切换与 AGC 重整，需要建立时间。接收机侧现有 `btnModeSet` 已有「通道帧 → 100 ms → 模式序列」的先例。

**为什么必须顺序而非并行**：若接收机先切、矩阵后切，在等待矩阵 ACK 的这段时间里，射频信号已进入上一通道的通路，会在接收机里产生一段错误的瞬态读数。

### 5.4 通道间隔离度测试的特殊时序

隔离度测试需要 A 组与 B 组指向**不同通道**，此时矩阵切换分两步：

```
① A 组切到 CH n（注入通道）   → CMD 0x01
② ── 间隔 ≥ 100 ms ──
③ B 组切到 CH m（读数通道）   → CMD 0x06    （m ≠ n）
④ ── 间隔 ≥ 100 ms ──
⑤ 接收机发 0D 11 m P 00 00 0A（接收机工作在读数通道）
```

**或者使用 CMD 0x09 一次完成**（A、B 两组同时切换且原子生效）：

```
① CMD 0x09 (chA=n, chB=m)     → 原子切换，两组均无中间态
② ── 间隔 ≥ 100 ms ──
③ 接收机发 0D 11 m P 00 00 0A
```

> CMD 0x09 优于分两步：两组状态在 < 1 µs 内同时改变，接收机不会看到任何中间态。
> 常规测试（chA = chB）也推荐用 0x09，语义更明确。

## 六、上位机侧实现约定

### 6.1 复用的既有设施

| 既有代码 | 复用方式 |
|---|---|
| `Common/SerialPortBase.cs` | 继承，已提供 `Open` / `SendBytes` / `DataReceived` / `Logger.LogSend` |
| `MatrixControl/IChannelSwitcher.cs` | 实现 `Connect` / `Disconnect` / `SwitchChannel` / `ConnectionChanged` |
| `UI/ReceiverControlPanel.cs` 的 `cmbMatrixPort` / `cmbMatrixBaud` / `btnMatrixConnect` / `btnMatrixDisconnect` | **零改动** |
| `Common/Logger.cs` | 收发帧自动记日志（黑底绿字区） |

### 6.2 接口需要扩展（重要）

`IChannelSwitcher` 当前只有 `SwitchChannel(int channel)` 一个切换方法，**无法表达 B 组独立切换**。

需要新增能力：

| 需求 | 建议 API |
|---|---|
| A 组（RF+LO）切通道 | 复用现有 `SwitchChannel(int channel)` |
| B 组（输出路）切通道 | 新增 `SwitchOutputChannel(int channel)` |
| 双组同时设置 | 新增 `SetChannels(int channelA, int channelB)` |
| 查询当前状态 | 新增 `QueryState()`（可选） |

**两种处理方案**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **甲：扩展 `IChannelSwitcher`** | 接口加 2~3 个方法 | 语义清晰，类型安全 | **接口签名已冻结，需走 M3 评审** |
| **乙：另立 `IOutputSwitcher`** | 新增独立接口，`MatrixSerialPort` 同时实现两者 | 不动已冻结接口 | 调用方要持有两个引用 |

**建议**：采用**方案乙**。理由：
- `IChannelSwitcher` 的签名冻结是 M3 阶段的既有约定，破坏它会影响已写好的评审记录
- 输出路切换是**独立职责**，用独立接口表达更符合"接口隔离"的项目原则
- `MatrixSerialPort` 同时实现两个接口，UI 侧可只持有一个实例

> 无论哪种方案，**`MatrixSerialPort` 是同一个对象**，串口连接是共享的，不需要开两个串口。

### 6.3 新增文件

| 文件 | 职责 |
|---|---|
| `MatrixControl/MatrixCommandBuilder.cs` | 帧构造与解析（纯逻辑，无 IO，可单元测试） |
| `MatrixControl/IOutputSwitcher.cs` | 输出路切换接口（方案乙） |
| `MatrixControl/MatrixSerialPort.cs` | 重写：真实实现，同时实现两个接口 |

### 6.4 帧构造 API 草案

```csharp
public static class MatrixCommandBuilder
{
    // 帧头
    public const byte FrameHeader1 = 0xAA;
    public const byte FrameHeader2 = 0x55;

    // 命令码 —— A 组（RF 路 + LO 路）
    public const byte CmdSwitchChannel  = 0x01;
    public const byte CmdIsolateA      = 0x02;
    public const byte CmdQueryChannelA = 0x03;

    // 公共
    public const byte CmdQueryVersion = 0x04;
    public const byte CmdReset        = 0x05;

    // 命令码 —— B 组（输出路）
    public const byte CmdSwitchChannelB  = 0x06;
    public const byte CmdIsolateB       = 0x07;
    public const byte CmdQueryChannelB  = 0x08;

    // 命令码 —— 双组同时设置
    public const byte CmdSetBothChannels = 0x09;

    // 状态码
```

### 6.5 `IOutputSwitcher` 接口草案（方案乙）


> `MatrixSerialPort` 同时实现 `IChannelSwitcher` 与 `IOutputSwitcher`，
> **共用同一个串口连接**，不需要开两个串口。

### 6.6 `SwitchChannel` 的实现约定

`IChannelSwitcher.SwitchChannel(int channel)` 是 `void` 返回，**无法向上层传递失败**。

处理方式：

```csharp
public void SwitchChannel(int channel)
{
    if (!IsConnected)
    {
        Logger.Log("[Matrix] 切换通道失败：未连接");
        return;   // 记录日志，不抛异常（与项目既有「失败只记日志」约定一致）
    }

    byte[] frame = MatrixCommandBuilder.BuildSwitchChannel(channel);
    SendBytes(frame);          // SerialPortBase.SendBytes 会自动 Logger.LogSend

    // 等待 ACK 并校验状态
    if (!WaitForAck(MatrixCommandBuilder.CmdSwitchChannel, timeoutMs: 500))
    {
        Logger.Log($"[Matrix] 切换通道 {channel} 超时");
        return;
    }
    if (_lastStatus != MatrixCommandBuilder.StatusOk)
    {
        Logger.Log($"[Matrix] 切换通道 {channel} 失败：状态码 0x{_lastStatus:X2}");
    }
}
```

**设计要点**：
- **不抛异常** —— 与项目既有约定一致（`OnChannelSelected` 已 catch，但驱动侧失败只记日志更安全）
- **失败必须记日志** —— 否则测试用错误通道的数据，报表完全失真
- **ACK 超时 500 ms，重试 3 次** —— 与 VISA 仪表的重试机制保持一致的工程习惯

### 6.7 连接与断开

| 操作 | 行为 |
|---|---|
| `Connect(port, baud)` | 打开串口 → 发送 `CMD 0x04`（版本查询）→ 收到合法版本帧才算连接成功 → `ConnectionChanged?.Invoke(true)`；超时或响应非法则关闭串口并 `Invoke(false)` |
| `Disconnect()` | 发送 `CMD 0x05`（双组复位为隔离态）→ 关闭串口 → `ConnectionChanged?.Invoke(false)` |

**连接即校验版本**：可提前发现固件与上位机协议不匹配，避免测试跑到一半才发现。

### 6.8 日志输出

`SerialPortBase` 已内置：

- 发送：`Logger.LogSend(bytes)` → 形如 `>> AA 55 01 01 03 04`
- 接收：`Logger.LogRecv(bytes)` → 形如 `<< AA 55 01 01 00 01`

协议解析失败时追加一行 `Logger.Log("[Matrix] 帧解析失败：...")`，便于现场排查。

## 七、版本兼容策略

| 变更类型 | 处理 |
|---|---|
| 新增命令码 | 上位机忽略未知 CMD 的 ACK，记日志；向后兼容 |
| 新增状态码 | 上位机按「非 0 = 失败」处理，不做细分；向后兼容 |
| 修改帧格式 / 校验算法 | **不兼容**，须同步升级固件与上位机，通过 CMD 0x04 版本号识别 |
| 扩展 PAYLOAD | 向后兼容（LEN 字段已支持变长） |

**版本号约定**：`L<major>.<minor>.<patch>`，major 变更即协议不兼容。
