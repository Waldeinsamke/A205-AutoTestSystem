## 〇、一页速读

### 0.1 这块板子干什么

一块**纯数字板**，只有一个职责：**把上位机的串口命令翻译成 6 根开关控制线上的高低电平**，再通过一根 8 芯线缆送到 3 块现成的射频圆盘模块。

它**不含任何射频器件、没有任何射频走线、没有任何阻抗控制要求**。射频信号完全不经过这块板 —— 射频只走 SMA 同轴线。

### 0.2 接口一览

| 接口              | 数量 | 说明                                  |
| --------------- | -- | ----------------------------------- |
| USB-A（Device 口） | 1  | 供电（取 5 V）+ 通信（枚举为 COMx）；A-A 双头线直插电脑 |
| 8 脚排针           | 1  | 去三块圆盘模块：6 根控制线 + 3.3 V + GND        |
| SWD 排针（3 脚）     | 1  | 下载 / 调试固件                           |
| TTL 调试口（3 脚，可选） | 1  | 无 PC 时的调试与量产测试                      |

> **本轮出图范围（已决策 · 2026-10-28）**：**阶段 A 最小系统** —— USB-A + CH340C + AMS1117-3.3 + STM32G030K6Tx + 6 根控制输出 + 8 脚排针 + SWD + 去耦 + 必需测试点。
> **LED、TTL 调试口、USB ESD 阵列不在本轮**，留待阶段 B（见 §4.11）。
> **【已决策 · 2026-10-28】电脑接口改为 USB-A（Device 口）**，原 Type-C 方案作废，理由与改法见 §4.5。

### 0.3 三条必须先懂的结论

> **结论 1：8 根线里没有 V4，因此"全隔离态"（八个端口全部 50 Ω 终端）无法由驱动板实现。**
> PE42482 的 V4 是一个独立的隔离位；把它固定在 GND 就等于"永远允许接通"，切通道时靠 V1/V2/V3 三位编码选路。代价是：驱动板**没有"断开"这个动作**，永远有一路处于导通状态。详见 §2.6。
>
> **【已决策 · 2026-10-28】接受该后果，J1 保持 8 脚排针。** 驱动板不实现隔离命令，固件对 `0x02 / 0x05 / 0x07` 统一回 `STATUS = 0x03`（不支持）。若将来反悔，§2.6 的"可选扩展"给出了改 10 脚的完整路径，但驱动板需重画。

> **结论 2：A 组的两块圆盘（RF 路 + LO 路）是并联硬连的，因此永远同步切换。**
> 这是有意的 —— RF 与 LO 必须指向同一个接收机通道，并联连法天然保证同步，不可能失配。详见 §2.5。

> **结论 3：三条红线，违反会永久损坏 PE42482。**
> ① 控制脚（V1/V2/V3/V4/LS）**绝对不得超过 3.6 V**，严禁 5 V 驱动；
> ② 圆盘模块的 J4 脚位在实测之前**不得盲接**；
> ③ 圆盘上的 V4 脚必须被可靠地拉到 GND（若悬空或上拉，模块永远不导通，系统完全无信号且无任何报错）。详见 §3.3、§6.2。

### 0.4 需求一句话版本

> 一块 USB 供电的 3.3 V 控制板，用 6 根 GPIO 驱动 PE42482 的 3 位通道编码，其中 3 根并联驱动"RF 路 + LO 路"两块圆盘，另 3 根独立驱动"输出路"圆盘，8 根线里还有 1 根 3.3 V 和 1 根 GND 给三块圆盘并联供电。

## 一、背景与设计目标

### 1.1 背景

A211 五通道测试系统的射频开关矩阵由"控制板 + 2 块 PE42482 圆盘模块"组成。控制板上有大量本项目用不到的功能，且其协议面向 A211。

A205 需要 8 通道，因此需要 **3 块圆盘模块**（RF 路 / LO 路 / 输出路），并重做一块精简的控制板。

### 1.2 设计目标

| #  | 目标                                    | 验收含义                    |
| -- | ------------------------------------- | ----------------------- |
| G1 | 驱动板只做"USB ↔ 命令通道 + 3.3 V 供电"，**不碰射频** | 板上无 RF 器件、无 RF 走线、无阻抗要求 |
| G2 | 驱动板与圆盘模块**物理分离**，通过线缆对接               | 板上只有一个 8 脚连接器           |
| G3 | 上位机通过 USB 直连驱动板，无需 RS-232 转换器         | 插上 USB-A 双头线即出现 COMx    |
| G4 | 3.3 V CMOS **直驱**，不加电平转换              | 控制线直接连 MCU GPIO         |
| G5 | **A 组与 B 组必须独立**，以支持「通道间隔离度」测试        | 6 根控制线，分 3+3            |
| G6 | 线缆总根数最小化（**8 根**，1 个 8 脚接口）           | 这是已定的约束，不可增删            |
| G7 | 圆盘模块供电由驱动板提供（3.3 V）                   | 驱动板 LDO 直接带 3 块圆盘       |

### 1.3 与 A211 原控制器的对照

| 项      | A211 原控制板             | A205 驱动板（本设计）                         |
| ------ | --------------------- | ------------------------------------- |
| 与圆盘的接口 | 9 角梯形接口，多组 6 位排针      | **单个 8 脚排针**                          |
| 控制线    | 每模块 V1/V2/V3/V4（4 根）  | **每组 V1/V2/V3（3 根）**，共 6 根            |
| 隔离位 V4 | 由控制板驱动                | **不引出**，在圆盘侧固定为 GND（见 §2.6）           |
| LS     | 控制板驱动                 | **不引出**，在圆盘侧固定（正码/反码待实测，见 §6.2）       |
| 电脑接口   | Device 接口 + RS-232 线缆 | **USB-A 直连**（A-A 双头线，CH340C 枚举为 COMx） |
| 圆盘供电   | 独立                    | **驱动板 3.3 V 并联供 3 块**                 |
| 冗余功能   | 多                     | 已全部剔除                                 |

### 1.4 非目标（明确不做）

- 不做射频通道切换本身（由圆盘模块完成）
- 不做信号源 / 频谱仪控制（由上位机直接控）
- 不做接收机侧协议（接收机串口独立）
- 不做 5 V 控制电平兼容（圆盘若为 5 V 供电，需加电平转换，见 §8 阻塞项 2）

### 2.5 A 组 / B 组分组设计依据

**A 组 = 圆盘 #1（RF 路）+ 圆盘 #2（LO 路），共用 3 根线。**

理由：RF 与 LO 在任何测试中都必须指向**同一个**接收机通道，没有需要错开的场景；并联硬连使同步成为物理保证，不可能失配。

**B 组 = 圆盘 #3（输出路），独立 3 根线。**

理由：「通道间隔离度」测试要求 RF 输入通道 ≠ IF 输出读数通道：

```
RF 信号源 → A 组（切 CH1）→ 接收机 CH1 的 RF 口（注入强信号）
                                        ↓ 接收机内部串扰
接收机 CH2 的 IF 输出口 → B 组（切 CH2）→ 频谱仪（读漏过来的信号）
```

若输出路与 A 组共用控制线，此场景**根本无法构造**，隔离度测试只能得到恒定无效的结果。
（项目规划书 §4.3.5 第 16 项「通道间隔离度」当前为 ⬜ Stub，正是等待此能力落地。）

**切换 B 组完全不影响 A 组，反之亦然** —— 这是 A/B 分离的唯一目的。

### 2.6 由「8 根线」架构导出的三条后果（必须知晓）

#### 后果 1：没有 V4 ⇒ 没有"全隔离态"

> **【已决策 · 2026-10-28】接受。J1 = 1×8 排针（2.54 mm），不增加 V4 线。**
> 配套的软件约定：协议中的 `0x02 / 0x05 / 0x07` 三条隔离命令在固件中**保留但返回** **`STATUS = 0x03`（不支持）**，这样上位机的既有代码不会崩，只是这三条命令无效。

PE42482 真值表中，**V4 是独立于 V1/V2/V3 的隔离位**：`V4 = 1 且 V3=V2=V1=0` → 8 个端口全部 50 Ω 终端吸收（安全态）。常规选路时 `V4 = 0`。

8 根线方案不引出 V4 ⇒ V4 只能在**圆盘侧**被固定。固定为 GND ⇒ 芯片永远处于"允许接通"状态。

| 影响   | 说明                                                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------ |
| 无法实现 | "断开射频通路"这一动作。驱动板没有"关断"命令                                                                                           |
| 上电瞬态 | 上电瞬间 V1/V2/V3 电平不确定，可能先接通一个随机通道再被固件改写                                                                              |
| 测试影响 | 若射频源在驱动板未就绪时已输出功率，接收机某个通道会瞬间收到信号                                                                                   |
| 缓解办法 | ① 6 根控制线各加 **10 kΩ 下拉**（见 §4.7），使上电默认码固定为 `000`，避免"随机通道"；② 上位机流程上，**先 mute 信号源，再连矩阵，最后开信号源**；③ 若确实需要物理断开，见下方"可选扩展" |

**可选扩展（不推荐现在做，但记录在案）**：若后续确认必须具备隔离能力，可把排针改为 **10 脚**，增加 `A_V4` 与 `B_V4` 两根。届时驱动板 GPIO 充足（STM32G030 有 29 个 GPIO），协议里已有的 `0x02 / 0x05 / 0x07` 三条隔离命令即可直接启用。**当前按 8 脚实现，软件侧对这三条命令返回"不支持"。**

#### 后果 2：三块圆盘共用一对供电线

| 影响         | 说明                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------- |
| 电流极小       | PE42482 的 IDD 仅 120\~200 µA，三块并联约 0.6 mA，供电线压降可忽略                                                    |
| 但共阻抗耦合不可忽略 | 三块模块共用同一根 3.3 V 与同一根 GND 回流，理论上可相互串扰                                                                 |
| 处理         | ① 线缆中 3.3 V 与 GND 各用独立导体；② **每块圆盘模块的 VDD 脚旁必须有 100 nF 就近去耦**（若模块上没有，需加贴片电容）；③ 控制线用双绞或排线，避免切换瞬间耦合到相邻线 |

#### 后果 3：射频不经过线缆 → 线缆质量不敏感

8 根线里**没有射频线**，射频全部走 SMA 同轴。因此这根线缆的屏蔽、阻抗、长度**不影响射频性能**，只影响控制信号的完整性。这是本架构的最大优点之一 —— 线缆只跑 µA 级电流和 3.3 V CMOS 电平。

## 三、PE42482 电气约束（设计红线）

### 3.1 射频拓扑（背景知识）

| 参数   | 规格                                        |
| ---- | ----------------------------------------- |
| 类型   | SP8T（Single Pole 8 Throw），吸收式（Absorptive） |
| 射频引脚 | **9 个 = 1 公共端 RFC + 8 分路 RF1\~RF8**       |
| 功能   | **1 路输入 → 8 路输出**，任一时刻仅一路导通               |
| 频率范围 | 10 MHz \~ 8 GHz                           |
| 封装   | 24-lead QFN，4 × 4 × 0.85 mm               |
| 控制脚  | V1、V2、V3、V4、LS（5 个）+ VDD + GND            |

### 3.2 ⚠️ 电气红线（数据手册 DOC-75785-3 Table 1 / Table 2）

| 项目            | 限制                  | 本设计的取值                  |
| ------------- | ------------------- | ----------------------- |
| **控制脚绝对最大额定** | **−0.3 V \~ 3.6 V** | **3.3 V 直驱，严禁 5 V**     |
| 数字输入高电平 VIH   | ≥ 1.17 V            | 3.3 V ✅                 |
| 数字输入低电平 VIL   | ≤ 0.6 V             | 3.3 V CMOS ✅            |
| 数字输入电流 V1\~V4 | 5 µA                | MCU GPIO 驱动能力（mA 级）余量充足 |
| 数字输入电流 LS     | 10 µA               | —                       |
| VDD 推荐范围      | 2.3 / 3.3 / 5.5 V   | **3.3 V**               |
| 供电电流 IDD      | 120 \~ 200 µA       | LDO 余量充足                |

**由此得出的三条硬性设计要求：**

1. **MCU 必须是 3.3 V IO 器件**。本设计选 STM32G030K6Tx（3.3 V IO），其 I/O 在 VDD=3.3 V 下输出高电平为 VDD，即 3.3 V，满足 < 3.6 V。
2. **绝不可使用 5 V IO 的 MCU 直驱**。若将来必须换 5 V MCU，需加电平转换（如 74LVC2T45 / TXS0102）。
3. **控制线上严禁并联上拉电阻到 5 V**。允许的只有：MCU 直驱，或加 10 kΩ **下拉**到 GND（用于确定上电默认态）。

### 3.3 V4 与 LS 的处理（本架构下的具体接法）

| 引脚           | 本设计的处理                                | 说明                                 |
| ------------ | ------------------------------------- | ---------------------------------- |
| **V1/V2/V3** | 由 MCU GPIO 直驱，A 组 3 根 / B 组 3 根       | 见 §2.3                             |
| **V4**       | **在圆盘侧固定接 GND**（0 Ω 电阻位短接）            | 芯片永远处于"允许接通"态；驱动板无隔离命令。见 §2.6 后果 1 |
| **LS**       | **在圆盘侧固定**（接 GND = 正码，或悬空 = 反码，由实测决定） | 见 §6.2 检查项 3。三块模块必须一致              |

> **LS 内部有 1 MΩ 上拉电阻到逻辑高**（数据手册 Note 1，原文）：
> *"LS has an internal 1 MΩ pull-up resistor to logic high. Connect LS to GND externally to generate a logic 0. Leaving LS floating will generate a logic 1."*
> 即：**接地 = 正码，悬空 = 反码**。反码时通道编号整体翻转（RF1↔RF8 互换），这是最容易埋雷的地方，必须实测（§7.2 R1）。

> **数据手册 Table 3 Note 1**：插损与隔离性能可通过 **LS 引脚（pin 1）良好的射频接地**来改善。
> → 若圆盘模块上 LS 悬空（反码），除了编码翻转，还可能带来额外插损。**建议统一改为正码（把 LS 通过 0 Ω 电阻接地）**，与 pSemi 官方 EVK（BOM DOC-75764 中 R1 = 0 Ω 0402 短接 LS）一致。

### 4.4 电源设计

**电源树**：

```
USB VBUS (5 V ±5%)
   ├──► CH340C.VCC (5 V 供电，V3 经 0.1 µF 接 VCC)
   └──► AMS1117-3.3.VI
            └──► AMS1117-3.3.VO = 3.3 V
                     ├──► STM32 VDD
                     ├──► CH340C.V3 (3.3 V 供电时 V3 直接接 VCC)
                     ├──► LED (经限流电阻)
                     └──► J1 pin7 (+3V3) → 三块圆盘 VDD
```

**AMS1117-3.3 要点**：

| 项            | 要求                                                                                                                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 输入电容         | 10 µF（钽/铝电解）+ 100 nF 就近                                                                                                                                                                                                                    |
| 输出电容         | **≥ 10 µF，且 ESR 需在厂商规定区间内** —— AMS1117 无输出电容会自激振荡，**不可省**                                                                                                                                                                                  |
| **散热片（Tab）** | ⚠️ **AMS1117 的 SOT-223 散热片 = pin 2 = VOUT（datasheet 原文："TAB IS OUTPUT"）** —— 因此 KiCad 用 `SOT-223-3_TabPin2` 是正确的（该封装的 Tab 焊盘编号为 2，会自动分配到 3.3 V 网络）。**绝对不要在散热片下方铺 GND 铜箔，否则 3.3 V 直接对地短路。** 正确做法：散热片下方留空（或铺 3.3 V 网络铜箔），散热靠底层完整 GND 平面经焊盘导热 |
| 输入最低电压       | 3.3 V 输出需输入 ≥ 4.4 V（压差 \~1.1 V）。USB 5 V 满足；若将来用 4.5 V 以下的外部电源需改用低压差 LDO                                                                                                                                                                    |

> **【已决策 · 2026-10-28】采用 AMS1117-3.3（SOT-223-3\_TabPin2）。**
> 理由：资料最通用、供应商都有货、手焊与返修最容易、当前负载余量充足（3.3 V 侧约 29 mA，AMS1117 可提供 1 A）。
> **两个必须记住的点**：① **输出电容 ≥ 10 µF 且 ESR 要落在厂商规定区间**，否则会自激振荡，表现为"3V3 电压大幅跌落 + 纹波异常"，建议 10 µF 铝电解/钽 + 100 nF 陶瓷并联；② 封装为 `SOT-223-3_TabPin2`，**Tab 散热片接哪个网络必须核对**（§8 阻塞项 5）。
> 若日后换 SOT-23-5 低压差 LDO（ME6211C33M2 / AP2112K-3.3），输出电容可放宽到 1 µF。

**电流预算**：

| 负载                | 5 V 侧       | 3.3 V 侧      |
| ----------------- | ----------- | ------------ |
| CH340C            | \~12 mA     | —            |
| STM32G030 @64 MHz | —           | \~12\~24 mA  |
| AMS1117 静态        | \~5 mA      | —            |

### 4.5 USB-A 接口设计（Device 口）

> **【已决策 · 2026-10-28】电脑接口由 Type-C 改为 USB-A（Device 口）**，用 USB-A 双头数据线（A-A Male-to-Male）直插电脑。

**为什么放弃 Type-C**：

| # | 理由                | 说明                                                                           |
| - | ----------------- | ---------------------------------------------------------------------------- |
| 1 | **兼容性更好**         | 工控机、台式机、笔记本扩展坞几乎都保证有 USB-A；Type-C 在台式机 / 工控机上并不普及                            |
| 2 | **避开"充电线不带数据"的坑** | 市面大量 Type-C 线是纯充电线，D+/D− 不通 → 插上不枚举 COM 口，且现场很难一眼看出是线的问题；A-A 数据线普及率高得多       |
| 3 | **少两个器件、两个错误点**   | Type-C 必须 CC1/CC2 各一颗 5.1 kΩ 下拉，漏装 / 错值 → **电脑根本不供电且毫无报错**；USB-A 不需要任何 CC 电阻 |
| 4 | **物理防呆**          | USB-A 只有一个插入方向，不存在反插问题                                                       |
| 5 | **规范允许**          | USB 2.0 规范定义了 "Double-A" 双头线，PC ↔ 本板的 A-A 连接是标准用法                            |

**代价**：USB-A 卧式座约 12 × 16 mm，比 Type-C 座（≈ 9 × 7 mm）占板 → **板尺寸由 50×40 mm 放宽到 60×40 mm**（见 §4.10）。

**不受影响的部分**：CH340C 一侧（UD+/UD− 引脚定义）、5 V → AMS1117 → 3.3 V 电源树、10 kΩ 下拉与控制电路**均无需改动**。

**引脚定义**（以 `Connector:USB_A` 符号为例）：

| 引脚 | 网络     | 处理                               |
| -- | ------ | -------------------------------- |
| 1  | VBUS   | 接 5 V 主电源（5 V 去耦 10 µF + 100 nF） |
| 2  | D−     | → CH340C 的 UD− (pin 6)           |
| 3  | D+     | → CH340C 的 UD+ (pin 5)           |
| 4  | GND    | 接 GND                            |
| SH | SHIELD | 接 GND（或经 RC / 直连板边地）             |

> ⚠️ **D+ / D− 不可接反**。以 KiCad `Connector:USB_A` 符号为准：**pin 1 = VBUS、pin 2 = D−、pin 3 = D+、pin 4 = GND**。
> 插座面板视角下的左右位置随连接器型号与丝印方向而定，**不要凭记忆判断** —— 画图时对照符号 pin 编号 + 所选连接器的数据手册逐脚核对。接反的表现是"**完全不枚举 COM 口**"，且 USB 线插拔时地/电源正常，容易误判为驱动问题。

**要点**：

1. **不需要任何 CC 电阻**（这是与 Type-C 最大的区别）。若沿用旧图残留的 5.1 kΩ 电阻，属于多余器件，直接不装即可。
2. **VBUS 与 GND 的走线要粗**（VBUS 建议 ≥ 30 mil，或铺铜），因为峰值电流不大但浪涌冲击有。
3. VBUS 附近放 **10 µF + 100 nF** 去耦。
4. **D+ / D− 必须差分走线，尽量等长、短、连续参考平面（同一层下方有完整地平面）**。USB 2.0 对此敏感。
5. SH 屏蔽壳：直连板边 GND，或串 1 nF + 1 MΩ（可选）。**本设计建议直连 GND**（USB 静电泄放路径）。
6. 若板上放 ESD 阵列（USBLC6-2SC6），放在 USB-A 座与 CH340C 之间，**靠近连接器**，并把 GND 接到干净的地。
7. **A-A 双头线必须是数据线**，不能是仅带电源的连线；选用带"双箭头"标识或 USB2.0 标志的线。
8. 板上 USB-A 座**朝板边放置**，A-A 线能垂直插拔，不顶到旁边元件。

### 4.6 CH340C USB 转串口设计（两个必须注意的坑）

**引脚定义**：

| 引脚    | 名称                                 | 处理                                                                  |
| ----- | ---------------------------------- | ------------------------------------------------------------------- |
| 1     | GND                                | GND                                                                 |
| 2     | TXD                                | → MCU 的 UART1\_RX (PA10)                                            |
| 3     | RXD                                | ← MCU 的 UART1\_TX (PA9)                                             |
| 4     | **V3**                             | **本设计为 3.3 V 供电 ⇒ V3 直接接 VCC(=3.3 V)**（5 V 供电时才是 V3 经 0.1 µF 接 VCC） |
| 5     | UD+                                | → USB-A 的 D+ (pin 3)                                                |
| 6     | UD−                                | → USB-A 的 D− (pin 2)                                                |
| 7, 8  | NC                                 | 内部时钟版本**无需晶振**，保持 NC                                                |
| 9\~14 | \~CTS \~DSR \~RI \~DCD \~DTR \~RTS | 悬空                                                                  |
| 15    | **R232**                           | **必须悬空/NC！**（见下方警告）                                                 |
| 16    | VCC                                | 3.3 V 或 5 V                                                         |

> ⚠️ **坑 1 —— R232（pin 15）绝不能接高电平。** CH340C 的 R232 脚**内部自带下拉电阻**，其作用是选择 TTL 电平模式。把它接到高电平会让 RXD 输出**反相**，表现为"上位机发什么、固件收到的全是乱码/取反字节"，极难定位。**本设计：R232 悬空（= 默认 TTL 模式）。**

> ⚠️ **坑 2 —— V3（pin 4）的接法随供电电压变化。** 3.3 V 供电时 V3 **必须直接接 VCC（3.3 V）**；5 V 供电时 V3 接 0.1 µF 到 VCC。接错会导致 USB 枚举失败或不工作。

**串口电平**：CH340C 的 IO 电平跟随 VCC。VCC = 3.3 V ⇒ 输出 3.3 V TTL，与 STM32G030 的 3.3 V IO **直连即可，无需电平转换**。

**Windows 驱动**：电脑端需安装 **WCH CH34x 驱动**（CH341SER / CH34xSER.EXE）。若枚举不出 COM 口，先查驱动而不是查硬件。

**可选：硬件流控**。本设计不使用（UART CTS/RTS 悬空），上位机用软件超时 + 校验和保证可靠性。

### 4.7 控制输出电路

**基本形式**：MCU GPIO 直连到 8 脚排针，中间可加 **1 kΩ 串联限流电阻**（可选但推荐）。

```
   PA0 ──┬── 1kΩ(可选) ──► J1.1 A_C1
         │
        10kΩ
         │
        GND
```

| 元件           | 是否必装           | 作用                                                                                       |
| ------------ | -------------- | ---------------------------------------------------------------------------------------- |
| **10 kΩ 下拉** | **必装**（6 根各一颗） | ① 固件接管前电平确定（默认 `000`）；② 抑制上电瞬态与线缆噪声；③ 防止 MCU 复位/下载模式下 GPIO 呈高阻时控制线悬空                     |
| **1 kΩ 串联**  | 推荐（6 根各一颗）     | 若接线错位把 3.3 V 误接到别的脚，或圆盘模块带电插错，限流保护 MCU 引脚与圆盘输入；代价是切换边沿略缓（RC ≈ 1 µs，对 227 ns 开关时间有影响，需评估） |
| **ESD 阵列**   | 可选             | 1×4 通道 ESD 保护（如 SP0504BAHTG），靠近排针                                                        |

> **关于 1 kΩ 串联电阻的取舍**：RC 时间常数 = 1 kΩ × （圆盘输入电容 + 线缆电容 ≈ 10\~50 pF）≈ 10\~50 ns，相对 PE42482 的 100 ns 上升时间可接受。但若实测发现切换边沿异常或误码，**去掉它**即可。**建议首版先不装，留焊盘**（0402 空焊盘），实测后再决定。

> **关于 10 kΩ 下拉的取值**：3.3 V 经 10 kΩ 下拉时，若 MCU 输出高电平，额外负载电流 = 330 µA/根 × 6 根 = 2 mA，对 MCU 无压力。PE42482 的输入电流仅 5 µA，10 kΩ 下拉形成的低电平 ≈ 0 V，远低于 VIL 0.6 V ✅。若想更轻，可改 47 kΩ 或 100 kΩ（仍能满足 < 0.6 V），但 10 kΩ 抗噪更好。

**3.3 V 输出到圆盘的电流**：PE42482 每根控制脚 5 µA，6 根共 30 µA —— 远小于任何 GPIO 的驱动能力，**不需要缓冲器**。

### 4.8 状态指示与调试接口

| LED          | 颜色  | 含义                   | 驱动方式                      |
| ------------ | --- | -------------------- | ------------------------- |
| `LED_PWR`    | 绿   | 3.3 V 正常             | 常亮，PA7 → 1 kΩ → LED → GND |
| `LED_STATUS` | 蓝/红 | 收到并成功执行一条命令时闪 100 ms | PA6 → 1 kΩ → LED → GND    |

**状态闪烁编码**（可选，便于现场排障）：

| 模式 | 含义             |
| -- | -------------- |
| 单闪 | 校验和错误          |
| 双闪 | 未知命令码          |
| 三闪 | 通道号越界（不在 1\~8） |
| 常亮 | 固件自检失败 / 处于错误态 |

**TTL 调试口**（可选，3 脚：3V3 / TX / GND 或 3V3 / TX / RX）：

- 目的：无 PC 环境下用 USB-TTL 线调试；量产测试时验证串口通路
- 走 PB0/PB1（UART2），与 UART1 并行输出同一份日志
- **注意**：调试口的 3V3 脚是**输出** 3.3 V（仅供逻辑参考），不要拿它给外部负载供电

### 4.9 BOOT0 / SWD / 复位

**这是 STM32G030 系列最容易踩坑的地方。**

> STM32G030 系列**没有像 F1/F4 那样的独立 BOOT0 专用脚**，BOOT0 是**复用脚**（在不同封装/型号上可能落在 **PA14（与 SWCLK 共脚）** 或 **PB8 / PB2（BOOT1）** 等位置）。
> **必须查你所用型号的 ST 数据手册 DS12991 的引脚图确认。**

**本设计的统一做法（对任何复用形式都适用）**：

```
        3V3
         │
   ┌─────┴─────┐
   │  跳线帽    │  2 脚（1-2 / 2-3）最简，或 3 脚排针
   │  2-3 短接  │  → 3V3 = 进系统 Bootloader
   │  1-2 短接  │  → GND = 正常从 Flash 启动
   └──┬─────┬──┘
      │     │
     GND   BOOT0 引脚（PA14 或 PB8 ...）
              │
             10kΩ
              │
             GND
```

| 项    | 要求                             |
| ---- | ------------------------------ |
| 下拉电阻 | **10 kΩ 到 GND**，必装             |
| 跳线帽  | 必装（3 脚排针 + 帽，或 2 脚 + 短接片）      |
| 测试点  | BOOT0 脚留 1 个测试焊盘，便于示波器/万用表确认电平 |
| 丝印   | 标注 `BOOT0` 与 `GND` / `3V3` 两档  |

**若 BOOT0 与 PA14/SWCLK 共脚**：跳线帽接到 PA14 上会干扰 SWD 调试（BOOT0=1 时无法用 SWD 连接）。实际工程中的通行做法是：跳线帽默认接 GND（正常运行），需要进 Bootloader 时把帽挪到 3.3 V，**此时放弃 SWD**（用串口烧录）。**这正是本板引出 TTL 调试口的价值所在 —— Bootloader 模式下可用串口烧录。**

**NRST**：

- 10 kΩ 上拉至 3.3 V（必装）
- 可选：100 nF 到 GND（RC = 1 ms，手动复位时更"软"）
- 可选：复位按键（按下拉低到 GND）

**SWD 排针**：至少引出 `3V3 / SWDIO / SWCLK / GND`（4 脚）方便用 4 芯排线接 ST-Link；再加一个 `NRST` 脚更好（5 脚）。

## 五、固件需求

### 5.1 上电流程

```
1. 尽早把 6 根控制线配置为推挽输出，并输出安全默认码（V1V2V3 = 000）
   —— 硬件已用 10 kΩ 下拉保证上电瞬间确定
2. 初始化 UART1（115200 8N1）
3. 上报版本帧（FW_VER）
4. 进入主循环，等待命令
```

**注意**：由于本架构**没有 V4**，不存在"先进隔离态再解除"的时序，固件也**不需要**做隔离→选路的中间步骤。

### 5.2 串口协议（沿用现有规范）

沿用 `docs/射频开关矩阵_通信协议规范.md` 的帧格式：

```
┌────────┬────────┬───────┬──────────┬────────┐
│ 0xAA   │ 0x55   │  CMD  │ PAYLOAD  │ CHECK  │
│  帧头1 │  帧头2 │ 命令码│ LEN + 数据│ Sum8   │
└────────┴────────┴───────┴──────────┴────────┘
```

**CHECK = (0xAA + 0x55 + CMD + LEN + PAYLOAD 各字节) & 0xFF**。

### 5.3 命令码与 8 线架构的对应

| CMD    | 名称         | 作用组   | 8 线架构下的行为                                          |
| ------ | ---------- | ----- | -------------------------------------------------- |
| `0x01` | 切换通道       | A 组   | `A_C1..A_C3` = 编码\[ch]                             |
| `0x02` | 隔离 A 组     | A 组   | **不支持** → 回 `STATUS = 0x03`（见下）                    |
| `0x03` | 查询 A 组当前通道 | A 组   | 返回当前通道（1\~8），无通道时 `0x00`                           |
| `0x04` | 查询固件版本     | —     | 返回版本字符串                                            |
| `0x05` | 复位为隔离态     | 双组    | **不支持** → 回 `STATUS = 0x03`；建议上位机改用 `0x09` 双组置通道 1 |
| `0x06` | 切换输出路通道    | B 组   | `B_C1..B_C3` = 编码\[ch]                             |
| `0x07` | 隔离输出路      | B 组   | **不支持** → 回 `STATUS = 0x03`                        |
| `0x08` | 查询输出路当前通道  | B 组   | 返回当前通道                                             |
| `0x09` | 同时设置两路     | A + B | `PAYLOAD = [chA, chB]`，两组各自切换                      |

**新增状态码**：

| STATUS     | 含义                                       |
| ---------- | ---------------------------------------- |
| `0x00`     | 成功                                       |
| `0x01`     | 校验和错误                                    |
| `0x02`     | 通道号越界（不在 1\~8）                           |
| **`0x03`** | **功能在当前硬件架构下不支持**（对应 0x02 / 0x05 / 0x07） |

> **对上位机的影响**：`射频开关矩阵_上位机对接说明.md` 中若有"隔离"相关按钮/调用，需在软件侧屏蔽或改为"切换到通道 1"。这属于 M3 阶段的软件改动，**不阻塞硬件**。

### 5.4 通道切换时序

```
A 组（圆盘 #1 + #2）：
1. 校验 ch ∈ [1, 8]，否则回错误 ACK，状态不变
2. 置 A_C1..A_C3 = 编码[ch]（三根同时更新，间隔 < 1 µs）
3. 回 ACK

B 组（圆盘 #3）：同上，用 B_C1..B_C3
```

**为什么不需要"先隔离再解除"**：PE42482 的开关时间 227 ns，V1/V2/V3 三位同时改变时，芯片内部是**先断开旧通路再建立新通路**（break-before-make），不存在两个通道短暂并联的窗口。手册给出的 TRISE/TFALL = 100/130 ns 即为该过程的表征。

**A 组与 B 组完全独立**：切换 B 组不影响 A 组，反之亦然。

### 5.5 通道编码映射（⚠️ 必须实测填表，不得推导）

固件以查表方式实现，**两张表**（A 组 / B 组），即使当前内容相同也保留两张（便于以后换板不改结构）：

```c
/* 索引 = 通道号 - 1，值 = {A_C1, A_C2, A_C3} 三位组合（bit0=A_C1, bit1=A_C2, bit2=A_C3）
 * ⚠️ 映射必须以实测确认为准，不得凭公式推导。
 *    实测流程见 docs/射频开关矩阵_接线与验收手册.md §五。 */
static const uint8_t g_channel_code_a[8] = {
    /* CH1 */ 0x0,   /* 待实测 */
    /* CH2 */ 0x0,   /* 待实测 */
    /* CH3 */ 0x0,   /* 待实测 */
    /* CH4 */ 0x0,   /* 待实测 */
    /* CH5 */ 0x0,   /* 待实测 */
    /* CH6 */ 0x0,   /* 待实测 */
    /* CH7 */ 0x0,   /* 待实测 */
    /* CH8 */ 0x0,   /* 待实测 */
};
static const uint8_t g_channel_code_b[8] = { /* 同上，B 组 */ };
```

**校验规则**（固件或上位机可内置自检）：

- 8 组码值必须**互不相同**
- 8 组码值必须落在 `0x0 ~ 0x7`（V4 不参与通道选择）
- 驱动通道 1\~8 时，实际导通端口必须依次为 RF1 \~ RF8

> **填错的严重后果**：矩阵切到"通道 3"，实际导通的是"通道 5" → 接收机在收 CH3，信号却进了 CH5 → 读数为 −∞ 或极低值，**系统不会报任何错**，报表数据完全失真。**必须实测。**

### 5.6 异常与安全

| 异常                          | 处理                       |
| --------------------------- | ------------------------ |
| 串口超时无命令                     | **保持当前通道不变**（不自动切走）      |
| 上位机断开                       | 同上。矩阵不应因上位机异常而改变通路状态     |
| 收到越界通道号（<1 或 >8）            | 回错误 ACK（`0x02`），状态不变     |
| 收到未知命令码                     | 回错误 ACK（`0x01` 或新码），状态不变 |
| 收到本架构不支持的命令（0x02/0x05/0x07） | 回 `STATUS = 0x03`，状态不变   |
| 校验和不匹配                      | 回错误 ACK，状态不变             |
| 看门狗复位                       | 复位后输出默认码（`000`），上报复位事件   |

### 6.3 三块模块的分配与射频接法

| 模块    | 用途       | 公共端 RFC 接             | 分路 RF1\~RF8 接         | 控制组     |
| ----- | -------- | --------------------- | --------------------- | ------- |
| 圆盘 #1 | **RF 路** | RF 信号源输出              | 接收机 CH1\~CH8 的 RF 输入口 | **A 组** |
| 圆盘 #2 | **LO 路** | LO 信号源输出              | 接收机 CH1\~CH8 的 LO 输入口 | **A 组** |
| 圆盘 #3 | **输出路**  | 接收机 CH1\~CH8 的 IF 输出口 | 频谱仪输入                 | **B 组** |

> ⚠️ **方向不可接反**：公共端是 **RFC**，分路是 **RF1\~RF8**。接反后信号从 8 个分路同时散出，等效于没有切换功能，且不会有任何报错。
> **判断方法**：用信号源从 RFC 灌入，逐个测 RF1\~RF8，只有接法正确时才是"只有一路有信号、其余在噪声底"。

### 6.4 输出路插损的方案取舍（待决策）

输出路只有 70 / 750 MHz，但 PE42482 在此频段仍有 **0.7\~0.8 dB** 插损。增益报表的计算式为 `等效增益 = peak − RF功率`，**中频路径的插损会直接体现在报表数值上**。

| 方案                     | 输出路插损         | 成本                     | 说明            |
| ---------------------- | ------------- | ---------------------- | ------------- |
| **A. PE42482**（与另两块统一） | 0.7 \~ 0.8 dB | 无额外成本                  | 插损作为标定值写进软件补偿 |
| **B. 50 Ω 继电器**        | < 0.1 dB      | 4 组双刀继电器 ≈ ¥40 + 额外驱动板 | 需另做一块小驱动板     |

**建议**：Mode3 增益本已存在约 11 dB 偏差待排查（见 §9 风险 6）。若用 PE42482，这 0.8 dB 会与原有问题叠加、更难定位根因。**倾向方案 B**，但它会引入第 4 块板和额外供电，需权衡。**此项不影响驱动板本体设计**，可并行决策。
